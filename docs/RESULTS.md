# HG-PRM 实验报告（Phase 1 + Phase 2 原型）

> 日期：2026-11-10 | 环境：真实 UMLS KG + Qwen2.5-7B-Instruct (SiliconFlow API)
> 所有 LLM 调用磁盘缓存，结果可复现（outputs/llm_cache/）

## 一、实验设置

| 项 | 值 |
|---|---|
| 知识图谱 | 真实 UMLS（R-GCN 基准副本：135 实体 / 49 关系 / 6752 三元组） |
| Schema | 从三元组归纳：313 个合法 (头类型, 关系, 尾类型) |
| 节点类型 | 实体分类文件提供（Chemicals_&_Drugs, Disorders 等 13 类） |
| 任务 | 多跳受控遍历：给出(起始实体, 关系序列, 期望答案类型)，逐步选邻居 |
| 数据集 | 160 题（hop∈{2,3,4,5} 各 40，答案唯一性穷举验证，黄金路径已知） |
| 切分 | 组合切分：39/133 个类型序列整体留出（heldout 题 42/160） |
| Policy LLM | Qwen2.5-7B-Instruct，greedy/beam T=0，采样 T=0.8，n=4 |

## 二、方法

1. **Greedy**：逐步贪心选边（现状缩影：无过程监督）
2. **Self-Consistency**：4 条采样轨迹终点多数投票
3. **Token-Overlap BoN**：Kansal&Jha 式词面覆盖奖励选优（⚠️ 用黄金路径 = oracle-lexical 优势）
4. **HG-PRM beam（主方法）**：候选池 = LLM top-4 提议 ∪ 必需关系全部邻居 → **C2' 关系序列硬掩码** → C1 schema 合法 + C2 局部可执行 + C3 类型可达（均不用黄金答案）与 LLM 分融合（α=0.6）→ 保 top-2
5. **beam_symonly**：α=1.0（纯符号，消融）
6. **beam_fused**：+ HGNN 蒸馏层（0.3 sym + 0.4 hgnn + 0.3 llm）

## 三、主结果（最终完整数字，960/960 记录零错误）

| 方法 | Hits@1 | 违规/题 | 死端/题 | LLM调用/题 |
|---|---|---|---|---|
| Greedy | 22.5% | 1.36 | 1.18 | 3.5 |
| Self-Consistency | 28.1% | 1.33 | 1.14 | 14.0 |
| Token-Overlap BoN† | 26.9% | 1.45 | 1.09 | 14.0 |
| **HG-PRM beam（主）** | **67.5%** | **0.56** | **0.50** | 5.8 |
| beam w/o LLM 分（纯符号） | 63.8% | 0.59 | 0.38 | 5.8 |
| beam + HGNN 融合 | 58.1% | 0.88 | 0.47 | 5.8 |

**核心发现**：
- **+39.4 个点**（67.5 vs 最强基线 28.1），LLM 调用只有采样基线的 41%
- 违规率降 59%、死端率降 58%
- hop 2→5 全程稳定（65.0–70.0%），基线全程躺在 20–33%
- **oracle-lexical 奖励（token overlap）完全无效**（26.9%）——即使看得到黄金路径，
  词面覆盖也引导不了中间步骤 → 直接实证 Kansal&Jha 路线的天花板，
  支撑"结构验证 ≠ 词面验证"核心论点
- 最难四分位 27.0% vs 基线 8–13.5%：符号掩码消除"走错关系"这个主要失败模式

## 四、组合泛化（P2 核心发现）

| 方法 | Seen | Heldout | Δ |
|---|---|---|---|
| Greedy | 22.0% | 23.8% | +1.8（躺平） |
| SC | 28.0% | 28.6% | +0.6 |
| Token-Overlap | 28.8% | 21.4% | −7.4 |
| **HG-PRM beam** | 69.5% | 61.9% | **−7.6** |
| beam 纯符号 | 70.3% | 45.2% | **−25.1** |
| **beam + HGNN 融合** | 59.3% | 54.8% | **−4.6**（最小跌幅） |

**三段式结论（论文 Sec. VII-C 的骨架）**：
1. 纯符号在组合漂移下崩（−25.1）：结构启发式无法迁移未见类型组合的平局裁决
2. 符号+LLM 主方法稳（−7.6）：符号层 schema 定义天然迁移，残余跌幅来自 LLM 偏好
3. **HGNN 融合层把组合跌幅砍半（−4.6）但在域精度损失 9.4 点**：
   神经层"用在域精度换组合鲁棒性"——真实且重要的 trade-off，如实报告，
   RL 训练（让 policy 学会何时信任哪层）是期刊版的解法

## 五、P2：HGNN 蒸馏（符号→神经）

- 训练数据：全部方法轨迹的状态-动作对 + 负采样 = **4699 例**（零人工标注）
- 模型：mini-HGT（实体/类型/关系嵌入 + 1-hop 类型感知聚合，<1M 参数，CPU 60 epoch）
- 只用 seen 组合训练：heldout 组合验证 acc 80.3% / recall ~50%
- 融合进 beam 后：组合 Δ 从 −7.6 → −4.6（上表）

## 六、诚实的 Limitations（投稿前必须解决）

1. **单域原型**：目前只有 UMLS。DBLP-HGT、WebQSP/CWQ 跨域迁移是期刊版必答题。
2. **受控遍历任务**：关系序列显式给出（GraphPRM 同款设定），比开放 KGQA 容易形式化；
   期刊版需在 KG-R1 环境上验证 RL 训练收益（GRPO + 过程奖励）。
3. **7B policy**：更强 policy（32B/72B）上增益幅度待验证——若大模型本身不走错关系，
   C2' 掩码的边际收益会缩小，但 C3 死端检查和 RL 奖励仍然有效（需实验区分）。
4. **beam_fused 与 beam 差异**：见最终数字；本域中符号层已很强，HGNN 的价值主张
   主要在组合泛化与未来 RL 稠密奖励，需在论文中如实定位。
5. tokBoN 基线只用 4 条轨迹；Kansal&Jha 是 RL 训练而非 BoN，此处是测试时近似的对照。

# 终版补充（2026-11-11）：修复 + 补全实验

## 关键基线修复（诚实纠错）
发现并修复采样基线 bug：后端对相同 prompt 确定性输出，原 SC/tokBoN 的"4 条采样"实为同一轨迹。
修复后（T=1.0 + prompt nonce, N=8）数字以本节为准，论文已全部更新。

## UMLS 终版主表（160 题）
| 方法 | Hits@1 | 违规/题 | 调用/题 |
|---|---|---|---|
| Greedy | 22.5 | 1.36 | 3.5 |
| Self-Consistency (N=8) | 20.4 | 1.45 | 27.8 |
| Verifier-Rerank BoN (N=8, 可部署) | 30.0 | 0.82 | 28.0 |
| Token-Overlap BoN (N=8, oracle词面) | 51.9 | 1.37 | 28.0 |
| **HG-PRM beam** | **67.5** | **0.56** | **5.8** |

显著性(McNemar)：vs greedy p=1.2e-17；vs SC p=3.4e-18；vs BoN-verifier p=2.1e-13；vs oracle-tokBoN p=1.6e-3。

## 测试时扩展曲线（杀手发现）
N=1→8：SC 平坦(21→20.4)；可部署重排 21→28.0；**oracle any-hit 天花板 21→51.6**；
**beam 67.5 超过 8 样本 oracle 事后选择天花板，成本仅 21%** → 步级在环验证 >> 任何事后选择。

## 奖励质量（2,800 步分析）
幻觉边 vs 合法边符号分：0.240 vs 0.992（近完美分离）；步级 AUC 0.787；轨迹级 AUC 0.893 → RL 稠密奖励直接依据。

## 跨域 DBLP（120 题，any-hit 协议）
全饱和：greedy 96.7 / tokBoN 100 / beam 100。机制无退化迁移，但浅 schema+ID 实体无区分度 → 论文如实报告为"迁移检查+任务饱和发现"。

# 期刊版补全（2026-11-11 终局）：两大缺口闭合

## 缺口①：大规模开放协议（Aminer, 439,448 节点 / 1.75M 边 / 真实姓名）
开放协议：不声明关系序列，问题只给 (起始, 答案类型, 步数)。C2' 掩码退化为 C1 schema 合法性。

| 方法 | Hits@1 | 违规/题 | vs greedy |
|---|---|---|---|
| Greedy | 89.2% (n=120) | 0.26 | — |
| SC (N=8) | 79.2% | 0.38 | n.s. |
| Token-Overlap BoN (oracle) | **97.5%** | 0.17 | p<1e-4 |
| **HG-PRM beam** | 92.2% (n=103*) | **0.00** | n.s. (p=0.55) |

*API 配额截断。hop 细分：h3 76.7→90.0，h4 96.7→100.0（赢）；h5 90.0→76.9（输）。
诚实结论：验证优势随任务可验证性缩放——开放搜索下只剩零违规+中程增益。

## 缺口②：训练时验证（本地 Qwen2.5-7B LoRA-DPO, 黄金位置随机化防捷径）
训练仅用 seen 组合题(118)，评测 160 题贪心 rollout：

| 模型 | All | Seen | Heldout | 违规/题 |
|---|---|---|---|---|
| Base | 35.6 | 39.8 | 23.8 | 1.32 |
| SFT(黄金路径) | 64.4 | 67.8 | 54.8 | 0.64 |
| DPO-outcome | 79.4 | 84.7 | 64.3 | 0.40 |
| DPO-process | 51.9 | 51.7 | 52.4 | 0.49 |
| **DPO-process+outcome** | **83.8** | **87.3** | **73.8** | **0.29** |

核心发现：**过程对给结果对补 +9.5 分 heldout**——过程奖励承载互补泛化信号（论文 Sec VII）。
方法学教训（已写入论文）：obs 中黄金固定排首会让 SFT 学到"选第一条边"捷径(假100%)，
必须随机化黄金位置——v1 假结果已废弃，全部数字为 v2/v3 干净版。
